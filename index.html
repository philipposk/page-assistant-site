A talking assistant that actually does things in your app.

Drop it into any website. It reads the page, runs your real features by voice or text, and never makes up results. It even publishes an llm.txt so other AI agents can drive your app.

Why it doesn't hallucinate

Most "AI on your site" widgets let the model claim it did something. This one can't.

1 · It can only do what you register

You expose real functions as "capabilities". No capability for a request? It says so — it never pretends.

2 · Your numbers, not the model's

Each capability returns the real result and renders the user-facing text. The model narrates around facts, it doesn't invent them.

3 · A validator catches lies

If the model writes a number no function actually returned, it's rejected and replaced with the real output. Proven in tests.

Add it in three steps

1

Run the backend

A tiny Node service holds your API keys and proxies the model + voice. Keys never reach the browser.

npm i @page-assistant/server
# set ANTHROPIC_API_KEY (or OpenAI / OpenRouter)
npx page-assistant-server   # :8787
2

Embed the widget

One script tag, or an import in React/Next/Vue. A floating mascot appears bottom-right.

<script src="https://unpkg.com/@page-assistant/widget/dist/page-assistant.global.js"></script>
3

Register your real actions

Map the things your app can do to functions. That's the whole integration.

PageAssistant.init({
  serverUrl: "http://localhost:8787",
  appName: "My App",
  voice: true,
  capabilities: [{
    name: "simulate_cross",
    description: "Simulate a cross and predict yield + height.",
    parameters: { type:"object", properties:{
      a:{type:"string"}, b:{type:"string"} }, required:["a","b"] },
    run: ({a,b}) => myApp.simulate(a,b),   // your REAL function
    render: (r,a) => `Yield ${r.yield}/100, height ${r.low}–${r.high} cm.`
  }]
});

Two ways to run it: Lite and Agent

Lite is the widget above: one script, any website, your actions run in the page. Agent moves the assistant's brain to your server, next to your data and your logins, and gives React and Next.js apps a dock that can change real data safely and show people around. Same grounding, same "never makes up results" — pick per app, or run both.

LiteAgent
FitsAny site: a script tag or an import (React, Vue, plain HTML)React 19 / Next.js apps with a server (Vercel works)
The thinking runsIn the browser; your server only passes each message to the modelOn your server, signed in as the user
ActionsFunctions on the page (filter, calculate, open)Your real API — create, rename, delete — with your database's own access rules
Before anything riskyAsks first for actions you markShows a confirm card. Only your click runs it, once; the AI alone never can
Text from strangersGrounding + validatorAfter reading someone else's text (a document, a message), it changes nothing without your OK
Shows people aroundLinks in repliesOpens pages, rings the right control, narrates guided tours
When things go wrongRate limits on the proxyPer-user limits, time limits, automatic retry and a fallback model — and a plain-language reply, never a hang
Chat historyOn the device or in the user's accountThe same — same tables, same adapters

Pick Lite when…

it's a static or non-React site, you want one script tag, or the useful actions are things the page itself can do.

Pick Agent when…

the assistant should change real data (add, rename, delete, send), you need a confirm step you can trust, or it should demo your product with tours.

Add Agent mode to a Next.js app

Not on npm yet — vendor it from GitHub, like the apps that already use it.

1

Vendor the SDK

Add it as a submodule, build it, and point your package.json at the packages.

git submodule add \
  https://github.com/philipposk/page-assistant.git \
  vendor/page-assistant
cd vendor/page-assistant
npm ci --include=dev && npm run build

# package.json → dependencies
"@page-assistant/core":   "file:vendor/page-assistant/packages/core",
"@page-assistant/server": "file:vendor/page-assistant/packages/server",
"@page-assistant/widget": "file:vendor/page-assistant/packages/widget",
"@page-assistant/react":  "file:vendor/page-assistant/packages/react"
2

One route

Your sign-in check and your real actions. Mark anything that can't be undone "confirm".

// app/api/pa/agent/route.ts
import { createAgentRoute } from
  "@page-assistant/server/next";

export const { GET, POST } = createAgentRoute({
  appName: "My App",
  getUser: () => currentUserId(),   // no user → 401
  context: () => supabaseForUser(), // tools act as the user
  tools: [{
    name: "delete_note",
    description: "Delete a note for good.",
    risk: "confirm",                   // a card, then your click
    parameters: { type:"object",
      properties:{ id:{type:"string"} }, required:["id"] },
    run: async ({ id }, ctx) => {
      const { error } = await ctx.app
        .from("notes").delete().eq("id", id);
      return error ? { ok:false, error:"Couldn't delete it." }
                   : { ok:true };
    },
    render: () => "Deleted.",
  }],
});
3

One component

Drop the dock into your layout. Tag what it may point at with data-pa-anchor.

"use client";
import { AgentDock } from "@page-assistant/react";
import { useRouter } from "next/navigation";

export function Assistant() {
  const router = useRouter();
  return (
    <AgentDock
      endpoint="/api/pa/agent"
      navigate={(p) => router.push(p)}
      voice
    />
  );
}

// <ul data-pa-anchor="notes.list">…</ul>

It talks. And listens.

Free out of the box using the browser's built-in voices, or switch on ElevenLabs + Whisper for studio-quality speech. Talk over it and it stops instantly — a real conversation, not a press-to-talk toy.

  • Voice in (speech-to-text) and voice out (text-to-speech)
  • Barge-in: interrupt any time
  • Reads the page on first open, so it understands where the user is

Other AI agents can use your app too

The assistant publishes a machine-readable contract. Any agent can discover what your app does and drive it — getting the same grounded, validated results a human would.

GET /llm.txt

A plain-language description of your app and every action its assistant can take.

GET /.well-known/llm-actions.json

The same, machine-first: a JSON manifest of capabilities and their parameters.

POST /v1/agent

The living assistant. Another agent sends a request in plain English; your app does it.
